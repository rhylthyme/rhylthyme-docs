Embed Rhylthyme in your app¶

Everything on this page uses code that already ships: the @rhylthyme/timeline package (timing engine, SVG renderer, the <rhylthyme-timeline> player element and the validator, with zero dependencies and TypeScript types) and the hosted MCP server at mcp.rhylthyme.com. Pick the section that matches what you need:

You want Use Runs
A playable timeline with timers, Start/Pause and Done buttons Live player browser
A picture of the schedule Static chart browser or Node
Start and end times to drive your own UI Timings only browser or Node
Validation, analysis or a shareable link from your server Hosted service your backend
The same validation and analysis with no server In the browser browser or Node

To see the pieces working together, open Potion Night at the Crooked Tower, a toy app in one HTML file: a recipe book that validates and explains, a schedule planned back from midnight, the player, and a tower scene driven only by the step events. View its source.

The examples load the package from jsDelivr, pinned to 2.0.0-beta.7. In a bundled app, npm install @rhylthyme/timeline@2.0.0-beta.7 instead. Each HTML snippet runs as-is when saved to an empty .html file and opened in a browser.

1. Live player¶

Two script tags (the engine first, then the element) and one tag:

<!doctype html>
<meta charset="utf-8">
<script src="https://cdn.jsdelivr.net/npm/@rhylthyme/timeline@2.0.0-beta.7/src/index.js"></script>
<script src="https://cdn.jsdelivr.net/npm/@rhylthyme/timeline@2.0.0-beta.7/src/element.js"></script>

<rhylthyme-timeline
  src="https://raw.githubusercontent.com/rhylthyme/rhylthyme/main/examples/recipe/birthday-party.json"
  mode="player" speed="60" time-format="minutes"></rhylthyme-timeline>

<script>
  const el = document.querySelector('rhylthyme-timeline');
  el.addEventListener('rt-load', () => console.log('loaded', el.timings));
  el.addEventListener('rt-step-began', (e) => console.log('began', e.detail.stepId, 'at', e.detail.time, 'by', e.detail.by));
  el.addEventListener('rt-step-ended', (e) => console.log('ended', e.detail.stepId, 'at', e.detail.time, 'by', e.detail.by));
  el.addEventListener('rt-complete', (e) => console.log('all done at', e.detail.time));
</script>

src is fetched with fetch(), so it must be same-origin or served with CORS (raw.githubusercontent.com is). To pass a program you already hold, set the property instead: el.program = programObject.

Attribute Values
src (or the program property) a URL to fetch, or a program object
mode player (default) or static (the chart alone, no controls or cursor)
speed playback multiplier, default 1
time-format minutes (mm:ss), seconds, hours (h:mm:ss), clock (wall time)
start-at ISO 8601 start time for clock
theme light, dark, cookbook; or set the CSS variables --rt-bg, --rt-fg, --rt-accent, --rt-border, --rt-panel, --rt-muted

Methods: start(), pause(), stop(), toggle(), seek(seconds) (while paused), startStep(id), completeStep(id). Read-only properties: currentTime, status, timings, stepStates.

Events bubble and cross the shadow boundary; times are seconds from the start of the program. To follow a run, listen to rt-step-began and rt-step-ended: they fire once per step per run, for every step, with what caused each transition (by). Player events lists every event and the rules for dropped runs, seeking and stopping.

Event When detail
rt-load the program is loaded and planned program
rt-start, rt-pause, rt-tick playback starts, pauses, advances time
rt-step-began any step begins (once per run) stepId, time, by
rt-step-ended any step ends (once per run) stepId, time, by
rt-seek seek() moved the playhead from, to
rt-complete every step is done time
rt-stop playback is stopped
rt-run-record once per run: the run record record, outcome

rt-step-start and rt-step-complete still fire, but only for steps a person starts or the player finishes; see Older step events.

In React¶

The element is a standard Web Component, so React needs no wrapper package: import it once and it registers itself. A component that sets the program as a property and forwards two events works in React 18 and 19:

import { useEffect, useRef } from 'react';
import '@rhylthyme/timeline/element';   // registers <rhylthyme-timeline>

export function RhylthymeTimeline({ program, speed = 1, onStepComplete, onComplete }) {
  const ref = useRef(null);

  useEffect(() => { ref.current.program = program; }, [program]);

  useEffect(() => {
    const el = ref.current;
    const stepDone = (e) => onStepComplete?.(e.detail);
    const allDone = (e) => onComplete?.(e.detail);
    el.addEventListener('rt-step-complete', stepDone);
    el.addEventListener('rt-complete', allDone);
    return () => {
      el.removeEventListener('rt-step-complete', stepDone);
      el.removeEventListener('rt-complete', allDone);
    };
  }, [onStepComplete, onComplete]);

  return <rhylthyme-timeline ref={ref} mode="player" speed={speed} />;
}

Use it as <RhylthymeTimeline program={program} onComplete={() => ...} />. Without a bundler, load the two script tags from section 1 in your HTML and drop the element import. In TypeScript, the package's types give document.querySelector('rhylthyme-timeline') the element's methods and typed rt-* events.

2. Static chart¶

In the browser, renderTimeline(container, program, options) draws the same SVG the CLI's rhylthyme render writes:

<!doctype html>
<meta charset="utf-8">
<script src="https://cdn.jsdelivr.net/npm/@rhylthyme/timeline@2.0.0-beta.7/src/index.js"></script>

<div id="chart"></div>

<script>
  fetch('https://raw.githubusercontent.com/rhylthyme/rhylthyme/main/examples/recipe/birthday-party.json')
    .then((r) => r.json())
    .then((program) => {
      Rhylthyme.renderTimeline(document.getElementById('chart'), program, { style: 'web', palette: 'vivid' });
    });
</script>

In Node, renderTimelineSvg(program, options) returns the SVG as a string (npm install @rhylthyme/timeline@2.0.0-beta.7):

const fs = require('fs');
const { renderTimelineSvg } = require('@rhylthyme/timeline');

const program = JSON.parse(fs.readFileSync('birthday-party.json', 'utf8'));
fs.writeFileSync('birthday-party.svg', renderTimelineSvg(program, { style: 'publication' }));

require() and ES module imports both give every function by name (import { renderTimelineSvg } from '@rhylthyme/timeline'). Options include style (classic, web, publication), palette, colorBy (track or task), startAt (wall-clock axis), legend (off by default: true draws the key to arrows and marks, and the player's legend attribute does the same), title and width; the full table is in the package README.

3. Timings only¶

computeStepTimings(program) resolves every trigger and returns start and end seconds per step, for drawing your own UI or scheduling notifications:

<!doctype html>
<meta charset="utf-8">
<script src="https://cdn.jsdelivr.net/npm/@rhylthyme/timeline@2.0.0-beta.7/src/index.js"></script>

<pre id="out"></pre>

<script>
  const program = {
    schemaVersion: '0.1.0',
    programId: 'tea',
    name: 'Tea and toast',
    tracks: [
      { trackId: 'tea', name: 'Tea', steps: [
        { stepId: 'boil', name: 'Boil water', startTrigger: { type: 'programStart' },
          duration: { type: 'fixed', seconds: 180 } },
        { stepId: 'steep', name: 'Steep', startTrigger: { type: 'afterStep', stepId: 'boil' },
          duration: { type: 'fixed', seconds: '4m' } },
      ] },
      { trackId: 'toast', name: 'Toast', steps: [
        { stepId: 'toast', name: 'Toast bread', startTrigger: { type: 'afterStep', stepId: 'boil', offsetSeconds: '-2m' },
          duration: { type: 'fixed', seconds: 150 } },
      ] },
    ],
  };

  const timings = Rhylthyme.computeStepTimings(program);
  // { boil:  { start: 0,   end: 180, duration: 180, trackId: 'tea',   resolved: true },
  //   steep: { start: 180, end: 420, ... },
  //   toast: { start: 60,  end: 210, ... } }
  document.getElementById('out').textContent = JSON.stringify(timings, null, 2);
</script>

Pass { actual: { stepId: { start, end } } } as a second argument to re-plan around what has really happened; the player does this on every tick.

4. Hosted service from a backend¶

mcp.rhylthyme.com/mcp is an MCP server, and a single JSON-RPC POST calls any tool with no session handshake and no account. Send Accept: application/json to get a plain JSON reply. The endpoint does not send CORS headers, so call it from your server, not from page JavaScript.

Tool Arguments result.structuredContent
validate_program program valid, errors, warnings, stats
analyze_schedule program, optional finishAt or startAt (ISO 8601) makespanSeconds, criticalPath, bindingConstraints, resourceConflicts, steps (with wall-clock startAt when you pass a time), wallClock
visualize_schedule program url (a public live-timeline link), shareId, imageUrl, makespanSeconds

visualize_schedule publishes: anyone with the link can open the timeline. Each finding in errors and warnings has a code; the finding codes reference explains the codes, with an example and a fix. It lists the codes of the package's validator (section 5); the hosted server still runs its own copy, which also reports a few older structure codes that are not listed there (missing_program_id, missing_step_id and the like, where the package reports schema_required).

With curl:

curl -s https://mcp.rhylthyme.com/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json' \
  -d '{
    "jsonrpc": "2.0", "id": 1, "method": "tools/call",
    "params": { "name": "validate_program", "arguments": { "program": {
      "schemaVersion": "0.1.0", "programId": "tea", "name": "Tea",
      "tracks": [{ "trackId": "tea", "name": "Tea", "steps": [
        { "stepId": "boil", "name": "Boil water", "startTrigger": { "type": "programStart" },
          "duration": { "type": "fixed", "seconds": 180 } } ] }] } } }
  }'

With fetch (Node 18 or newer, or any server runtime with fetch):

async function rhylthyme(tool, args) {
  const res = await fetch('https://mcp.rhylthyme.com/mcp', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Accept: 'application/json' },
    body: JSON.stringify({ jsonrpc: '2.0', id: 1, method: 'tools/call', params: { name: tool, arguments: args } }),
  });
  const reply = await res.json();
  if (reply.error) throw new Error(reply.error.message);
  if (reply.result.isError) throw new Error(reply.result.content[0].text);
  return reply.result.structuredContent;
}

const program = {
  schemaVersion: '0.1.0', programId: 'tea', name: 'Tea',
  tracks: [{ trackId: 'tea', name: 'Tea', steps: [
    { stepId: 'boil', name: 'Boil water', startTrigger: { type: 'programStart' },
      duration: { type: 'fixed', seconds: 180 } },
  ] }],
};

const check = await rhylthyme('validate_program', { program });
console.log(check.valid, check.errors);

const plan = await rhylthyme('analyze_schedule', { program, finishAt: '2026-11-26T18:00:00-05:00' });
console.log(plan.makespanSeconds, plan.steps.map((s) => [s.name, s.startAt]));

// Publishes a public link:
// const { url } = await rhylthyme('visualize_schedule', { program });

Save it as rhylthyme.mjs and run node rhylthyme.mjs. Every tool, including the catalog search and account tools, is listed in the MCP server reference.

5. Validate and analyze in the browser¶

The validator and analyzer behind validate_program and analyze_schedule also ship in the package, as @rhylthyme/timeline/schedule, so a page can check a program and plan it without calling any server. The findings and fix hints follow the hosted tools', and every code this validator reports is in the finding codes reference. The hosted server still runs its own copy, whose codes differ in places (it reports missing_program_id where this one reports schema_required, for one). In a page, browser/schedule.js is one script (about 470 KB, most of it the catalogue of lab instruments it checks) that sets window.RhylthymeSchedule:

<!doctype html>
<meta charset="utf-8">
<script src="https://cdn.jsdelivr.net/npm/@rhylthyme/timeline@2.0.0-beta.7/browser/schedule.js"></script>

<pre id="out"></pre>

<script>
  const program = {
    schemaVersion: '0.1.0',
    programId: 'tea',
    name: 'Tea and toast',
    tracks: [
      { trackId: 'tea', name: 'Tea', steps: [
        { stepId: 'boil', name: 'Boil water', startTrigger: { type: 'programStart' },
          duration: { type: 'fixed', seconds: 180 }, task: 'kettle' },
        { stepId: 'steep', name: 'Steep', startTrigger: { type: 'afterStep', stepId: 'boil' },
          duration: { type: 'fixed', seconds: '4m' } },
      ] },
      { trackId: 'toast', name: 'Toast', steps: [
        { stepId: 'toast', name: 'Toast bread', startTrigger: { type: 'afterStep', stepId: 'boil', offsetSeconds: '-2m' },
          duration: { type: 'fixed', seconds: 150 }, task: 'toaster' },
      ] },
    ],
    resourceConstraints: [{ task: 'kettle', maxConcurrent: 1 }],
  };

  const { validateProgram, analyzeSchedule } = RhylthymeSchedule;
  const lines = [];

  const check = validateProgram(program);
  lines.push('valid: ' + check.valid);
  for (const e of check.errors) lines.push(`${e.code}: ${e.message}\n  fix: ${e.fix}`);

  // Fix what it reported, then plan backwards from a finish time.
  program.resourceConstraints.push({ task: 'toaster', maxConcurrent: 1 });
  const plan = analyzeSchedule(program, { finishAt: '2026-11-26T08:00:00Z' });
  lines.push('valid now: ' + validateProgram(program).valid);
  lines.push('takes ' + plan.makespan + '; critical path: ' + plan.criticalPath.join(' → '));
  for (const s of plan.steps) lines.push(`${s.startAt}  ${s.name}`);

  document.getElementById('out').textContent = lines.join('\n');
</script>

It prints:

valid: false
task_not_constrained: Task "toaster" is used by steps but has no resourceConstraint.
  fix: Add {task:"toaster", maxConcurrent:N}. Every task used in a step needs a matching constraint.
valid now: true
takes 7m; critical path: boil → steep
2026-11-26T07:53:00.000Z  Boil water
2026-11-26T07:54:00.000Z  Toast bread
2026-11-26T07:56:00.000Z  Steep

In a bundled app or in Node, import it instead; the functions are typed:

import { validateProgram, analyzeSchedule } from '@rhylthyme/timeline/schedule';

analyzeSchedule also takes startAt instead of finishAt, and history (recorded runs) to add predicted durations. The result has makespanSeconds, criticalPath, bindingConstraints, resourceConflicts (each with a fix), steps and tracks.

The module also exports findingCodes, the catalogue the finding codes reference is generated from: per code its severity, summary, explanation, an example and the fix, so an app can show more than the one-line message:

import { validateProgram, findingCodes } from '@rhylthyme/timeline/schedule';

for (const f of validateProgram(program).errors) {
  const about = findingCodes.codes[f.code];
  console.log(`${f.code}: ${f.message}\n  ${about.explanation}\n  fix: ${f.fix}`);
}

The JavaScript validator and the Python one in the rhylthyme package are tested against each other on every example program, so a program this page accepts is one rhylthyme validate accepts. One rule differs today: a task without a resource constraint is an error here but only a --strict error in Python.
