    Finding codes¶

    Every finding the Rhylthyme validator reports has a code, a message, a where (the step, track or path it is about) and a fix. This page lists every code: what it means, a program that triggers it, and how to fix it. The codes are those of validateProgram in @rhylthyme/timeline/schedule.

    The hosted MCP server

    The MCP tool validate_program and the checks visualize_schedule runs before it publishes still use the server's own copy of the validator. It reports many of the codes below, and also these, which this page does not list: missing_program_id, missing_name, no_tracks, bad_track, missing_track_id, missing_track_name, bad_step, missing_step_id, missing_step_name, missing_start_trigger, bad_duration_type, fixed_without_seconds, variable_without_bounds, indefinite_without_default, choice_too_few_options and bad_alert. validateProgram reports each of those problems as a schema_* finding instead (they were removed from it in 2.0.0-beta.7).

    Errors make a program invalid; warnings and info notes do not. The Python column says what the rhylthyme package's validator reports for the same program: rhylthyme validate --json (the CLI, which checks the program as written) and validate_program_structured (the library, which expands replicates first). It reports schema problems as one schema_error and has no code of its own for many logic checks.

    This page is generated from the catalogue that @rhylthyme/timeline ships (findingCodes, version 2.0.0-beta.7 here) by tools/gen-finding-codes.js; a test fails when it falls behind.

    Base program¶

    Each example below is a fragment: its top-level keys replace those of this valid program, which has no findings at all.

    {
  "programId": "example",
  "name": "Example",
  "schemaVersion": "0.2.0-alpha",
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "prep",
          "name": "Prep",
          "duration": { "type": "fixed", "seconds": 300 },
          "startTrigger": { "type": "programStart" }
        },
        {
          "stepId": "cook",
          "name": "Cook",
          "duration": { "type": "fixed", "seconds": 600 },
          "startTrigger": { "type": "afterStep", "stepId": "prep" }
        }
      ]
    }
  ],
  "resourceConstraints": []
}

    Schema¶

    The program does not match the JSON Schema its schemaVersion selects (rhylthyme-spec's, bundled), or cannot be checked against it.

    Code Severity Summary Python

    not_json error The program cannot be written as JSON, so the schema was not checked. no
    schema_type error A value has the wrong JSON type. schema_error
    schema_enum error A value is not one of the allowed choices. schema_error
    schema_const error A value is not the one fixed value the schema allows. (not reachable today) schema_error
    schema_required error A required property is missing. schema_error
    schema_additionalProperties error An object has a property the schema does not allow. schema_error
    schema_minItems error A list has too few items. schema_error
    schema_maxItems error A list has too many items. (not reachable today) schema_error
    schema_minLength error A string is shorter than allowed (usually empty). schema_error
    schema_maxLength error A string is longer than allowed. schema_error
    schema_pattern error A string does not match the required pattern. schema_error
    schema_minimum error A number is below the minimum. schema_error
    schema_maximum error A number is above the maximum. schema_error

    schema_exclusiveMaximum error A number must be less than a bound and is not. (not reachable today) schema_error

    not_an_object¶

    Error. The program is not a JSON object.

    validateProgram was given an array, a string, a number, null or another non-object. Nothing else is checked: the result has this one error and stats null.

    Example. Passed to validateProgram as it is:

    ["not", "a", "program"]

    The whole value passed to validateProgram, not a fragment.

    Fix. Pass the full program object ({"programId": ..., "tracks": [...]}), not a string, an array or a wrapper around it.

    Python. Python reports nothing for it. Python raises on a program that is not an object instead of reporting a finding.

    not_json¶

    Error. The program cannot be written as JSON, so the schema was not checked.

    A JavaScript caller passed a value JSON cannot carry: a circular reference, a BigInt or similar. The JSON Schema check is skipped and this finding is reported in its place; the logic checks still run. Programs read from JSON text never get it.

    Example. Merged over the base program:

    { "metadata": { "bytes": 10 } }

    metadata.bytes is passed as a JavaScript BigInt, which no JSON text can carry.

    Fix. Pass plain JSON data: no circular references, BigInt values, functions or class instances.

    Python. Python reports nothing for it. Python always validates parsed JSON.

    schema_type¶

    Error. A value has the wrong JSON type.

    The schema expects a different type at this path: a string for a name, an integer for maxConcurrent, an object for a duration. Numbers written in quotes ("2") are strings. A value of the wrong type is reported once, not again by the oneOf/anyOf beside it.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "prep",
          "name": 7,
          "duration": { "type": "fixed", "seconds": 300 },
          "startTrigger": { "type": "programStart" }
        }
      ]
    }
  ]
}

    Fix. Write the value as the type the message names; for a quoted number, drop the quotes.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_enum¶

    Error. A value is not one of the allowed choices.

    The field accepts a fixed set of strings (an alert's level, a replicates mode, a trigger's event). Choices that tell apart the shapes of a oneOf, such as a duration's type, are reported as schema_oneOf instead.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "prep",
          "name": "Prep",
          "duration": { "type": "fixed", "seconds": 300 },
          "startTrigger": { "type": "programStart" },
          "alerts": [{ "event": "end", "level": "loud" }]
        }
      ]
    }
  ]
}

    Fix. Use one of the values listed in the message.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_const¶

    Error. A value is not the one fixed value the schema allows.

    A const keyword pins a field to one value.

    Not reachable today

    The bundled 0.3.0-alpha schema uses const only inside an if (metadata.varianceFactors), where a mismatch selects the other branch instead of failing, and 0.2.0-alpha does not use it. The checker supports it so that a schema update that starts using it keeps working; test/finding-codes.test.js fails when that happens, asking for an example here.

    Fix. Set the field to the value the message names.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_required¶

    Error. A required property is missing.

    Every program needs programId, name, tracks and resourceConstraints (or environment / environmentType); every track a trackId, name and steps; every step a stepId, name and startTrigger; every resource constraint a task and maxConcurrent. A missing startTrigger's fix names the step to chain after.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "steps": [
        {
          "stepId": "prep",
          "name": "Prep",
          "duration": { "type": "fixed", "seconds": 300 },
          "startTrigger": { "type": "programStart" }
        }
      ]
    }
  ]
}

    Fix. Add the property the message names.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_additionalProperties¶

    Error. An object has a property the schema does not allow.

    Some objects are closed (instrument, instrument actions, alerts, ...): any key besides the listed ones is an error, usually a typo. Programs, tracks, steps and triggers are open and accept extra keys.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "prep",
          "name": "Prep",
          "duration": { "type": "fixed", "seconds": 300 },
          "startTrigger": { "type": "programStart" },
          "instrument": {
            "tool": "shaker",
            "toolType": "bioshake",
            "command": "start_shake",
            "params": { "speed": 1000, "duration": 300 },
            "retries": 2
          }
        }
      ]
    }
  ]
}

    Fix. Remove the key or fix its spelling; the fix lists the keys allowed there.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_minItems¶

    Error. A list has too few items.

    Lists such as a compound trigger's triggers (at least 2), an instrument's start/end actions and a step's alerts must not be empty or too short.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "prep",
          "name": "Prep",
          "duration": { "type": "fixed", "seconds": 300 },
          "startTrigger": { "type": "programStart" },
          "alerts": []
        }
      ]
    }
  ]
}

    Fix. Add items, or remove the optional list entirely.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_maxItems¶

    Error. A list has too many items.

    A maxItems keyword caps a list's length.

    Not reachable today

    No bundled program schema (0.2.0-alpha, 0.3.0-alpha) uses maxItems where a failure is reported, so validateProgram cannot emit this code today. The checker supports it so that a schema update that starts using it keeps working; test/finding-codes.test.js fails when that happens, asking for an example here.

    Fix. Shorten the list.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_minLength¶

    Error. A string is shorter than allowed (usually empty).

    Names that must not be empty: an instrument's tool and command, an alert's message.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "prep",
          "name": "Prep",
          "duration": { "type": "fixed", "seconds": 300 },
          "startTrigger": { "type": "programStart" },
          "instrument": { "tool": "", "command": "start_shake" }
        }
      ]
    }
  ]
}

    Fix. Give the string a value, or remove the optional field.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_maxLength¶

    Error. A string is longer than allowed.

    An alert's message is at most 200 characters (code points, as Python counts them).

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "prep",
          "name": "Prep",
          "duration": { "type": "fixed", "seconds": 300 },
          "startTrigger": { "type": "programStart" },
          "alerts": [
            {
              "event": "end",
              "message": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
            }
          ]
        }
      ]
    }
  ]
}

    Fix. Shorten the string to the length the message names.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_pattern¶

    Error. A string does not match the required pattern.

    Schema 0.3.0-alpha constrains a few identifiers: metadata.varianceFactors keys (a letter, then letters, digits, _ and -) and a duration's calibratedFrom.programVersion ("sha256:" and 64 hex digits; inside a duration it is reported as schema_oneOf).

    Example. Merged over the base program:

    {
  "schemaVersion": "0.3.0-alpha",
  "metadata": { "varianceFactors": [{ "key": "2nd oven", "type": "number" }] }
}

    Fix. Make the string match the pattern in the message.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_minimum¶

    Error. A number is below the minimum.

    maxConcurrent is at least 1; durations and their bounds are at least 0.

    Example. Merged over the base program:

    { "resourceConstraints": [{ "task": "oven", "maxConcurrent": 0 }] }

    Fix. Use a value at or above the minimum the message names.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_maximum¶

    Error. A number is above the maximum.

    A taskResources fraction (the share of a resource a step occupies) is at most 1.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "prep",
          "name": "Prep",
          "duration": { "type": "fixed", "seconds": 300 },
          "startTrigger": { "type": "programStart" },
          "taskResources": [{ "name": "oven", "fraction": 1.5 }]
        }
      ]
    }
  ]
}

    Also emits task_not_constrained for the oven.

    Fix. Use a value at or below the maximum the message names.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_exclusiveMinimum¶

    Error. A number must be greater than a bound and is not.

    An instrument's or action's timeoutSeconds must be greater than 0.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "prep",
          "name": "Prep",
          "duration": { "type": "fixed", "seconds": 300 },
          "startTrigger": { "type": "programStart" },
          "instrument": {
            "tool": "shaker",
            "toolType": "bioshake",
            "command": "start_shake",
            "params": { "speed": 1000, "duration": 300 },
            "timeoutSeconds": 0
          }
        }
      ]
    }
  ]
}

    Fix. Use a value greater than the bound, or remove the optional field.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_exclusiveMaximum¶

    Error. A number must be less than a bound and is not.

    An exclusiveMaximum keyword caps a number below a bound.

    Not reachable today

    No bundled program schema (0.2.0-alpha, 0.3.0-alpha) uses exclusiveMaximum where a failure is reported, so validateProgram cannot emit this code today. The checker supports it so that a schema update that starts using it keeps working; test/finding-codes.test.js fails when that happens, asking for an example here.

    Fix. Use a value below the bound.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_oneOf¶

    Error. A value matches none, or more than one, of the allowed shapes.

    Durations, start triggers and the program's own startTrigger have several shapes told apart by their type. A value that fits none gets the closest shape's first problem (or the list of allowed types); a value that fits two (a duration with both seconds and timeString) is ambiguous.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "prep",
          "name": "Prep",
          "duration": { "type": "fixd", "seconds": 300 },
          "startTrigger": { "type": "programStart" }
        }
      ]
    }
  ]
}

    Fix. Follow the fix: set type to an allowed value, add the keys the closest shape needs, or remove the keys that make it ambiguous.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_anyOf¶

    Error. A value matches none of the alternatives it may take.

    A program needs resourceConstraints, environment or environmentType; an instrument needs a command, an until, or start/end actions. The message lists the alternatives.

    Example. Merged over the base program, without resourceConstraints:

    {}

    Fix. Add one of the alternatives the message lists.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_not¶

    Error. A value has a combination of keys the schema forbids.

    An instrument has both command and until (only one call can end the step); a program has resourceConstraints together with environment or environmentType.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "prep",
          "name": "Prep",
          "duration": { "type": "fixed", "seconds": 300 },
          "startTrigger": { "type": "programStart" },
          "instrument": {
            "tool": "shaker",
            "command": "start_shake",
            "until": { "command": "wait" }
          }
        }
      ]
    }
  ]
}

    Also emits instrument_bad_shape.

    Fix. Keep only one of the keys the message names.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

    schema_false¶

    Error. A value is present where the schema allows nothing.

    A false subschema forbids any value at that path.

    Not reachable today

    No bundled program schema (0.2.0-alpha, 0.3.0-alpha) uses a false subschema (a boolean schema) where a failure is reported, so validateProgram cannot emit this code today. The checker supports it so that a schema update that starts using it keeps working; test/finding-codes.test.js fails when that happens, asking for an example here.

    Fix. Remove the value.

    Python. Python reports schema_error. Python reports the first schema violation only, as one schema_error whose message is jsonschema's.

      "trackId": "main",

          "name": "Box",

    Warning. An alert would fire before the program starts, so it never fires.

    The instrument has a missing or empty tool, both command and until, no call or actions at all, an empty start/end/onAbort list, an action without a command, an unknown key or a bad timeoutSeconds. The schema reports the same problem (schema_*), with the program path; this finding says it in the instrument's own terms. The step's calls are not checked further.

    Example. Merged over the base program:

    {

      "trackId": "main",

    instrument_invalid_command¶

    Error. An instrument call is not valid for its tool type.

    The command does not exist for the toolType, or its params do not match the command's parameters (unknown, missing or of the wrong type). galago tool types are checked against galago-tools' commands, LabMCP servers against the LabMCP catalogue.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "shake",
          "name": "Shake",
          "startTrigger": { "type": "programStart" },
          "instrument": {
            "tool": "shaker",
            "toolType": "bioshake",
            "command": "start_shake",
            "params": { "rpm": 1000 }
          }
        }
      ]
    }
  ]
}

    Fix. Use a command and params the message lists for that tool type.

    Python. rhylthyme validate reports instrument_invalid_command; validate_program_structured reports logic_error. Needs rhylthyme-galago. From the rhylthyme-galago / rhylthyme-labmcp driver packages, when installed. validate_program_structured reports it as logic_error.

    instrument_over_limit¶

    Error. A LabMCP call's parameter is beyond the server's default limit.

    LabMCP servers refuse values past their safety limits (a maximum temperature, a series length, ...). The check uses each server's default limits; a lab may configure others.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "heat",
          "name": "Heat",
          "duration": { "type": "fixed", "seconds": 300 },
          "startTrigger": { "type": "programStart" },
          "instrument": {
            "tool": "stirrer",
            "toolType": "labmcp-ika",
            "start": [
              { "command": "set_temperature", "params": { "temperature_c": 200 } }
            ]
          }
        }
      ]
    }
  ]
}

    Fix. Use a value within the limit the message names, or raise the limit in the server's configuration.

    Python. rhylthyme validate reports instrument_over_limit; validate_program_structured reports logic_error. Needs rhylthyme-labmcp. From rhylthyme-labmcp, when installed. validate_program_structured reports it as logic_error.

    instrument_returns_early¶

    Error. A LabMCP call that replies as soon as it starts is used to end a step.

    Some calls (a syringe pump's infuse and withdraw) reply when the work starts, not when it is done; as the step's command or until call they would end the step at once.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "dose",
          "name": "Dose",
          "startTrigger": { "type": "programStart" },
          "instrument": {
            "tool": "pump",
            "toolType": "labmcp-new-era",
            "command": "infuse",
            "params": { "volume_ml": 1, "rate_ml_min": 1 }
          }
        }
      ]
    }
  ]
}

    Fix. Send it as a start action and give the step a duration at least as long as the dose.

    Python. rhylthyme validate reports instrument_returns_early; validate_program_structured reports logic_error. Needs rhylthyme-labmcp. From rhylthyme-labmcp, when installed. validate_program_structured reports it as logic_error.

    instrument_dose_outlasts_step¶

    Warning. A pump dose started by a step takes longer than the step.

    The dose's volume / rate is longer than the step's duration, so its end actions and the next steps start while the pump still runs.

    Example. Merged over the base program:

    {
  "tracks": [
    {
      "trackId": "main",
      "name": "Main",
      "steps": [
        {
          "stepId": "dose",
          "name": "Dose",
          "duration": { "type": "fixed", "seconds": 10 },
          "startTrigger": { "type": "programStart" },
          "instrument": {
            "tool": "pump",
            "toolType": "labmcp-new-era",
            "start": [
              { "command": "infuse", "params": { "volume_ml": 1, "rate_ml_min": 1 } }
            ]
          }
        }
      ]
    }
  ]
}

    Fix. Lengthen the step to at least the dose time, or lower the volume or raise the rate.

    Python. rhylthyme validate reports instrument_dose_outlasts_step; validate_program_structured reports nothing. Needs rhylthyme-labmcp. From rhylthyme-labmcp, when installed. validate_program_structured keeps only the errors of the instrument checks.

    instrument_catalog_not_loaded¶

    Warning. A LabMCP step was not checked because the LabMCP catalogue is not loaded.

    The browser entry of @rhylthyme/timeline/schedule (and browser/schedule.js) leaves out the LabMCP catalogue (about 350 KB). Until it is registered, each LabMCP step gets this warning instead of its checks. The Node entry always has it.

    Example. Merged over the base program:

}

    Validated with the browser entry before the LabMCP catalogue is registered.
